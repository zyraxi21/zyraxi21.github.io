# 视觉与体验持续复核

本次目标：以 Awwwards、Webby Awards、FWA 获奖作品的完成度为参照，检查排版、留白、视觉层级、色彩、动效、微交互、响应式与原创性。八维终审已完成，最终修复与验收记录见文末；各轮记录保留当时的证据与限制。

## 设计方向与约束

网站面向阅读工程、物理和开发笔记的人，首页负责帮助读者找到最近发布的内容，文章页负责支持持续阅读、检索与定位。

视觉方向为技术札记。日期、标题、分类与摘要承担不同信息层级；标题驱动的几何纹理作为站点识别元素，动效围绕导航、搜索、目录和复制反馈展开。

沿用既有主题色、思源正文与标题字体，以及 Ubuntu Mono / LXGW Bright Code GB 代码字体。个人站强调色为 #f7793c，横幅沿用 #f69128 与 #ff6651，正文为 #24292f，辅助文字为 #6b7280，页面底色为 #ffffff；深色沿用现有令牌。

```text
站点名称                         搜索 / 导航
主题横幅与站点信息
最近发布 / 全部文章               有内容时显示项目
日期
文章标题与分类
摘要
后续文章 / 分页
```

用户已确认保留原来按标题生成的 GeoPattern 配色与纹理显示方式。持续优化以现有主题的视觉风格为约束。

## 异步复制与玻璃截图复核（2026-10-02）

- 图表复制在点击处理期间提交包含 PNG 转换 Promise 的 `ClipboardItem`，避免等待转换后才请求写入；转换失败或不支持图片写入时仍回退至 SVG 文本。实现依据为 [WebKit 剪贴板说明](https://webkit.org/blog/10855/async-clipboard-api/)。
- 完整 Chrome 回归人为延迟图片转换 300ms，确认请求在点击期间、转换完成前发出；随后从真实剪贴板读取 PNG，核对深色底色和不透明度。Chrome 与 Firefox 的浅深色原生 PNG 写入均通过。
- Windows WebKit 的真实 PNG 写入被拒绝，但 SVG 文本回退成功；16×16 简单 PNG 的立即写入、延迟写入与 Promise 写入对照也被拒绝。因此不能把拒绝全部归因于本站转换，不能用该平台冒称已验证 iOS 或 macOS Safari 的图片复制。
- 等待滚动动画完成后，比较保留与临时关闭模糊的截图。Chrome 在 390、1440px 浅深色下的顶栏均有直接像素变化；当前手机样例的平均 RGB 像素差为浅色 2.30、深色 2.88，说明截图中的模糊实际参与了渲染。
- Firefox 的普通截图使用软件 `drawSnapshot`，绕过 WebRender 合成器；已核对本地 Playwright Firefox 的截图源码也使用这条路径。参见 [Firefox 合成截图说明](https://firefox-source-docs.mozilla.org/gfx/DebuggingWebRenderScreenshots.html)。计算样式正确或普通截图缺少模糊，均不足以证明实际合成效果。
- 改用 Firefox BiDi 和临时配置的 `remote.screenshot.use_readback` 读取合成画面，等待连续截图稳定并确认实际滚动位置和浅深色偏好；390、1440px 浅深色顶栏均有模糊像素变化。实验模式也出现局部文字绘制异常，因此这些截图只用于模糊参与合成的对照，不代替全页排版验收。
- 三个浏览器引擎分别验证减少动画偏好：导航与目录的过渡为 0.01ms，Escape 关闭后焦点回到入口，返回顶部在两帧内到达，滚动锁定正常释放，没有脚本异常。
- 当前浏览器范围的证据已按八维整理；实际手机的玻璃效果、软键盘、安全区域及 Safari 图片复制仍需补充直接证据。模拟结果不扩大为真机体验已通过的结论。

## 安全区域与原生缩放复核（2026-10-02）

- 在开启 `viewport-fit=cover` 后，分别读取顶部、左右和底部的安全边距。顶栏、横幅、锚点定位、页脚、搜索预览和浮动目录避开遮挡区域；修正左右留白共用左侧变量的问题。布局依据见 [WebKit 安全区域说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)。
- Chrome 通过 `Emulation.setSafeAreaInsetsOverride` 设置真实 CSS 环境变量，覆盖普通竖屏、带顶部遮挡的竖屏、低高度、左右横屏遮挡和 320px 双侧遮挡，浅深色共 14 组；修复后入口、搜索预览与目录没有越出可用范围。没有安全边距时顶栏与横幅布局相同，搜索预览边界差异低于 1px。
- 安全区域回归已加入维护测试，使用当前文章标题检索，检查搜索结果可见、浮窗边界、关闭后的焦点返回及环境变量清理。当前构建的完整 Chrome 浏览器回归与新增浅深色定向检查通过。
- Firefox 155 使用独立临时配置的原生 200% 缩放；窗口宽度 1280、1920、2560px 分别对应 640、960、1280px 的页面宽度，DPR 为 2，`visualViewport.scale` 为 1。全部 24 个索引页面在三种宽度与浅深色下完成 144 组检查，没有页面横向溢出或公式、图表错误；导航按页面宽度切换。
- 原生缩放证据来自浏览器配置、窗口几何与页面运行值。软件截图输出仍为 CSS 分辨率，不将它描述为两倍物理像素截图。
- Firefox 实验合成截图另设五种字体对照：未加载站点样式的系统 Arial、原始与分片正文字体、原始与分片代码字体；每种检查两个滚动位置，共 10 张。系统字体也复现局部竖向拉伸，故排除字体分片为该现象的原因；保留现有字体方案，这不替代真实 Firefox 设备的排版验收。
- 前端构建、严格 Jekyll 构建、ESLint、Prettier、98 个字体分片、22 项 JavaScript 和 34 项 Ruby 检查通过，当前站点 1705 项资源引用检查通过。真实手机的软键盘、玻璃合成和 Safari 图片剪贴板仍未实测。

## 最终复核（2026-10-03）

- 结合完整首页、长文、搜索预览、目录及浅深色截图，核对排版、留白、层级、色彩和原创性；保留思源宋体、工程笔记、既有橙色与标题纹理的视觉方向。动画、减少动画偏好、键盘焦点及搜索反馈另以实际交互验证，不以静态截图替代。
- 最后发现的两项布局问题已修正：手机密集分页的末行不再拉伸，按钮使用统一圆角与 6px 间距；页脚容器包含浮动文字，图标链接与文字居中对齐，图标入口与手机分页均保留至少 44px 的点击范围。
- 常规与每页一篇的密集分页分别覆盖 320、390、768、1440px 的浅深色布局，每站 16 组，两站共 32 组。检查实际点击范围、键盘焦点、悬停反馈、下一页地址及返回顶部，未见小点击范围或页面横向溢出。
- 依照用户确认保留评论自动加载，不将第三方评论的异步高度变化列为待修问题；未新增评论点击步骤。
- 最新严格构建与 1705 项资源引用检查通过。恢复自动评论后，当前构建的 125 个 JavaScript/CSS 资源与已完成分页验收的构建逐文件一致，评论模板、入口脚本、通用样式和 README 与本轮之前一致。
- 当前 151 组页面证据没有脚本异常或失败资源；最后的可见布局问题已修复，八维终审未发现继续调整的明确问题。原生缩放、多引擎交互和模拟安全区域的范围见上文；这些证据不扩大为真机实测或获奖认证。
